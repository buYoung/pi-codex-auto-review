# Brief Set: Codex Computer Use and Browser Use bridge for pi

## Purpose
- Ship `@buyong/pi-codex-computer-use`, a TypeScript pi extension that runs Codex Desktop's proprietary Computer Use / Browser Use runtime (`cua_repl` inside the Codex Desktop app) with the same host flow Codex uses: server launch per feature setting, Codex-shaped `_meta`, Codex-style confirmation dialogs, and turn-end notifications.
- Keep the package free of OpenAI runtime files and independent of `pi-codex-auto-review`, enable both features by default with per-feature on/off switches, cover the platforms Codex supports (macOS and Windows), document the Codex-subscription prerequisites, and perform only the installation steps the package can safely do itself.

## Shared Constraints
- The package never bundles, downloads, copies, or redistributes OpenAI runtime files (`cua_node`, `@oai/*`, bundled plugins, `Codex Computer Use.app`); it only executes what the Codex Desktop app installed, and service-app copying stays out of this set unless `02-feasibility.json` proves it necessary and the user approves it.
- No child writes under `CODEX_HOME` (`config.toml`, `plugins`, `computer-use`, `chrome-native-hosts*.json`) or the Chrome native-messaging registration, and no child reads `auth.json` or any credential file.
- Both feature flags default to `true`; a missing settings file means both on, an invalid file fails closed for that session with a reported error.
- Supported platforms are the ones Codex models Computer Use for: macOS (verified on this Mac) and Windows (implemented platform-neutrally, live verification deferred until a Windows machine with Codex Desktop is available); Linux and other platforms report `platform-unsupported`. Plugin-cache `.mcp.json` discovery is the primary, platform-neutral path; the app-bundle fallback exists for macOS only.
- Exactly one `cua_repl` server per pi session, started from `session_start` or the settings command (never the extension factory), with `CUA_REPL_ENABLED_SURFACES` and `NODE_REPL_TRUSTED_SERVICES` derived from the two feature flags; both flags off means no server and hidden tools. Only the unified `cua_repl` runtime is bridged; the legacy `node_repl` + `@oai/sky` path is excluded.
- Tool names are `mcp__cua_repl__js` and `mcp__cua_repl__js_reset` with descriptions, schemas, annotations, and server instructions passed through verbatim; `turn_ended` and `js_add_node_module_dir` are never exposed to the model.
- `tools/call` requests use `timeoutMs: 0` with pi's `signal` for cancellation and carry Codex-shaped `_meta` (`callId`, `sessionId`, `threadId`, `x-codex-turn-metadata`, `openai/confirmation_policies`).
- Confirmation responses match Codex shapes exactly (`accept` with optional `_meta.persist`, `decline`, `cancel`); the dialog never offers `Deny` for `codex_approval_kind: mcp_tool_call` requests; approval is by the user only.
- `@buyong/pi-codex-computer-use` is an independent extension: it never imports, depends on, documents integration with, or modifies `packages/pi-codex-auto-review`, and no child edits that package.
- Every live run that launches `Codex Computer Use.app`, controls an app, or opens a browser tab requires the user's approval in chat before it starts; live verification sessions run one at a time on this Mac.
- Handoff JSON files live in `docs/handoffs/computer-use/`, are valid JSON with a `status` field, embed any scratch script used, and contain no credentials, tokens, account identifiers, or user data beyond the app name and URL the user chose.
- Package shape follows `packages/pi-codex-auto-review` as a template only: ESM, `tsc` to `dist/`, pi packages as `peerDependencies` (`>=0.86.1`, dev-pinned `0.99.1`), Node `>=22.19.0`, Apache-2.0, `publishConfig.access: public`, Biome formatting; `@earendil-works/pi-mcp` is a direct dependency.
- `scripts/run-tests.mjs`, `scripts/verify-*.mjs`, and `.github/workflows/*` are not modified in this set; needed changes are recorded as follow-ups for the parent.
- No new automated test files or suites are added (not requested); verification uses `npm run build`, `npm run check`, `npm pack --dry-run`, live pi sessions, `mcp.log`, and bounded inspections of handoff files.
- `npm publish`, `npm run release`, tags, and pushes are excluded; the first publish is manual per `docs/publishing.md` after the user's separate approval.
- [deferred] Windows live verification, Linux support, `iab`/`mcpapps`/Edge backends, automatic-reviewer routing of confirmations, pi-side persistence of "Always allow", Codex's screenshot evidence retention, and grouped TUI rendering of consecutive calls.
