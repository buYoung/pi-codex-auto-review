# Brief Set: Codex image_gen as a Pi extension package

## Purpose
- Ship `@buyong/pi-codex-image-gen`, a TypeScript-only Pi package preserving the image_gen tool contract and using only Pi's supported `openai` provider, including its native ChatGPT subscription authentication, as designed in `docs/FDD/codex-image-gen.md`.
- Bundle the Pi-adapted `imagegen` skill and gate tool/skill exposure on Pi's configured OpenAI auth without overriding user choices.

> 최종 정정(2026-10-05): 구독 인증 자체도 Pi의 정식 `openai`를 사용하며 `openai-codex` 의존과 별도 Responses 방식 전환은 사용하지 않습니다. 아래 실행 순서·자식 브리프와 `07`·`08` 인계는 기존 단계의 이력을 유지합니다. 현재 인증·주소·헤더 계약은 FDD §9.1/§9.9와 `docs/handoffs/image-gen/09-openai-provider.json`을 따릅니다. 추가 실제 이미지 호출은 하지 않았으며, 과거 legacy 생성 성공을 현재 구현의 성공으로 전용하지 않습니다.

## Child Briefs
- [ ] `docs/briefs/2026-10-05-feat-codex-image-gen-01-tool-contract.md` — Scaffold the package and land the Codex-identical tool contract; exists because the schema, argument check order, error strings, and credential resolver are the stable surface every other child consumes (S1).
- [ ] `docs/briefs/2026-10-05-feat-codex-image-gen-02-backend.md` — Implement the Images API backend, retry, saving, and generation result; exists because HTTP, retry, response parsing, saving, and result shaping share one failure path (K2) distinct from argument and input handling.
- [ ] `docs/briefs/2026-10-05-feat-codex-image-gen-03-skill.md` — Bundle the Pi-adapted imagegen skill; exists because it is Markdown-and-license work with its own completion check (forbidden-token scan, skill loading) that no code child needs to wait on.
- [ ] `docs/briefs/2026-10-05-feat-codex-image-gen-04-ref-images.md` — Collect reference images for edits from local paths and session history; exists because file reading, format conversion, and session scanning fail differently from the HTTP path and only matter for edits.
- [ ] `docs/briefs/2026-10-05-feat-codex-image-gen-05-exposure.md` — Gate tool and skill exposure on openai credentials without overriding user choices; exists because exposure control lives in session/prompt events and branch records, a separate lifecycle from tool execution.
- [ ] `docs/briefs/2026-10-05-chore-codex-image-gen-06-verification.md` — Verify the integrated package against the FDD and record evidence; exists because the credential × operation live matrix, secret scan, and parity deviation list can only be produced on the integrated source.

## Shared Constraints
- `docs/FDD/codex-image-gen.md` is the design decision source; when a child finds a conflict between the FDD and Codex behavior, FDD §9.11 (Codex parity except the listed differences and user decisions) governs, and unresolvable differences are recorded in the child's `unresolved` for the FDD revision history rather than silently chosen.
- Codex reference source is the gitignored local copy `tmp/codex-main`; cite the file and symbol in handoffs so evidence survives without the copy.
- The package is TypeScript only: no Rust, Python, native binaries, or shelling out; runtime imports limited to `@earendil-works/pi-ai`, `@earendil-works/pi-coding-agent`, and Node built-ins; image decoding/conversion only through Pi's exported `convertToPng`; the skill directory contains Markdown, `LICENSE.txt`, and `NOTICE` only.
- Authentication and exposure use only Pi's supported `openai` provider. Treat the resolved credential as opaque; use auth.baseUrl, then provider.baseUrl, then the native default. Preserve additional headers and do not synthesize legacy JWT/account/turn requirements or rewrite the URL. No deprecated-provider lookup/fallback, credential-file access, separate login, or Responses redesign. Direct image requests and the existing tool contract remain in place.
- Tool name `image_gen`, label `Image generation`, Codex description with exactly the four FDD §9.3 edits, no `promptSnippet`/`promptGuidelines`, and annotations `readOnlyHint: false`, `destructiveHint: false`, `openWorldHint: true` are fixed across children.
- Fixed request values `model: "gpt-image-2"`, `quality: "auto"`, `size: "auto"`, `background: "transparent" | "opaque"`, no `n`; save root `<agentDir>/generated_images/<sessionId>/<toolCallId>.png` with the Codex sanitize rule and overwrite; the Codex output hint verbatim with the 1024-byte limit.
- Only `01-tool-contract` runs `npm install` and touches `package-lock.json`; if the lockfile has concurrent changes from another initiative, re-run `npm install` on the current tree instead of hand-merging.
- Pi version pin: all behavior claims are verified on `@earendil-works/*` 0.99.1; `peerDependencies` floor is `>=0.99.1`.
- `packages/pi-codex-auto-review`, `scripts/*.mjs`, `.github/workflows/*`, and `~/.codex/**` are never modified; `scripts/check-package.mjs` is not wired to the new package (follow-up for the user).
- No automated test files, lint config, or CI jobs are added (not requested); verification uses `npm run build`, `npm run check`, `npm pack --dry-run`, `node -e` inspections, a local mock HTTP server, and live `pi` sessions.
- Every live OpenAI call spends the user's quota: ask in chat before each paid session, state the call count, and record each run in the owning handoff without images or credentials.
- Handoff JSON files live in `docs/handoffs/image-gen/`, are valid JSON with a `status` field (`complete`, `blocked`, or `partial`), and contain no keys, tokens, account identifiers, or base64 image data; a `blocked` handoff stops successors and returns to the parent for a user decision.
- Intermediate checkouts stay buildable (`npm run build && npm run check` exit 0 after every child); placeholder behavior (`pending 02-backend`, `pending 04-ref-images`) must be removed by the named child before `06-verification`.
- Apache-2.0 obligations: the skill copy carries `LICENSE.txt`, the Codex `NOTICE` text, and modification notices; the tool description derived from Codex text is covered by the same notice.
- `npm run release`, `npm publish`, tags, and pushes are excluded from this set.
- [deferred] Quality/size/model options, `n > 1`, streaming, masks, custom TUI rendering, hiding the tool for non-vision models, pi-ai image registry provider, package README/usage docs, and generalizing `scripts/check-package.mjs`. The user approved correcting the FDD's authentication policy and its dependent sections; this does not activate the draft or establish whole-document commit-based conformance.

## Global Acceptance Criteria
- [ ] In a live Pi session with `openai` credentials, a prompt-only `image_gen` call returns the image and Codex hint and saves `<agentDir>/generated_images/<sessionId>/<toolCallId>.png`; `referenced_image_paths` and `num_last_images_to_include` edits each produce a new PNG with the source files unchanged.
- [ ] The declared `image_gen` schema deep-equals the Codex model-facing schema, every Codex error string is returned verbatim for its argument case, and Pi's generic `Validation failed for tool "image_gen"` message is unreachable.
- [ ] Scripted failure cases reproduce the Codex strings (`http 401 Unauthorized`, `429` without retry, `5xx` retried up to 5 attempts with 200 ms doubling backoff, `timeout`, decode error, `image generation returned no image data`).
- [ ] Without `openai` credentials, neither `image_gen` nor `imagegen` is declared; after `/login` they appear on the next prompt; a user-disabled `image_gen` is never re-enabled while credentials exist; `--exclude-tools image_gen` leaves no trace.
- [ ] The shipped skill tree is exactly five files, passes the forbidden-token scan, and loads via `--skill` and via the package manifest.
- [ ] `npm run build`, `npm run check`, and `npm pack --dry-run --json --ignore-scripts` (in the package) succeed on the final commit with the intended file list; `packages/pi-codex-auto-review`, `scripts/`, and `.github/` have no diff; `package-lock.json` changes only for the new workspace.
- [ ] `docs/handoffs/image-gen/06-verification.json` records every credential × operation cell with its real HTTP status, settles or explicitly leaves open each FDD §13 risk, lists parity deviations, and its secret scan over a non-empty population has no matches.
- [ ] No live run, handoff, or session file in the verification set contains a key, token, or `Bearer` value.
