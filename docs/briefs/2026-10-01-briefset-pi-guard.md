## Shared Constraints
- Each implementation owner derives concrete tests from verified APIs, agreed behavior and actual execution paths, writes and runs those tests alongside the implementation, corrects failures and records actual evidence. Test counts, IDs and fixture values are decided during implementation.
- No OpenShell integration, Docker runtime dependency, Pi core fork, package publication, real credential access, or paid/live model calls in automated tests.
- Treat Pi and explicitly trusted extensions as the controller. Native protection covers delegated local work; remote MCP server internals and arbitrary in-process third-party extension effects are separate trust boundaries.
- Bind every approval to the final tool identity, normalized input, resolved cwd, session, policy revision, and effective permission digest. Hard deny rules cannot be overridden by a model or cached grant.
- Preserve Pi tool names, argument/result schemas, structuredContent, error/exit semantics, streaming updates, caller AbortSignal, BashOperations timeout in seconds, and caller-supported options through the final consumer.
- Use the current Pi model runtime for separate tool-free review requests. All automated review/provider/UI interactions use injected doubles and an isolated Pi resource directory.
- Use disposable, owned fixture directories and synthetic secrets. Native proofs require successful permitted controls plus denied effects; missing dependencies, skipped cases, and denied nested sandbox launch are environment-blocked, not pass.
- Keep tests traceable to this brief's behavior and compatibility requirements. Reports identify actual test files and covered behavior, distinguishing unit doubles, simulated provider/UI integration and real OS enforcement.
- Read upstream tmp snapshots as references only. Confirm installed Pi 0.99.1 APIs against the copied 0.99.2 source before depending on them, and record exact selected sandbox package/runtime versions.
- Do not claim protected startup for ordinary Pi when a failed extension factory has been discarded. A declared guarded startup route must verify guard readiness before accepting execution.
- Do not stage, commit, install global packages, change machine sandbox settings, weaken a backend to make a test pass, or access an external Linux runner without the corresponding authorization.
- The current artifact-writing task is complete only after structural validation and separate per-document content/intent self-checks. It does not mark any implementation checkbox complete.
- Concrete test cases, counts and fixtures are derived during implementation after inspecting actual APIs and effect paths; this briefset fixes required behavior and verification obligations.
- Proposed npm test commands are introduced by child 01 and run only after their target files exist in the owning implementation stage. Document validators are authoring checks, not feature-test evidence.
- Shared request identity comprises exact tool/source, normalized args, resolved cwd, session, policy revision and permission digest. Preserve those bindings through model decisions, grants, native launch and final Pi consumers.
- Shared evidence schema uses explicit pass/fail/environment-blocked/not-run states and actual source/contract/runtime versions. A required missing, empty, duplicate, skipped or blocked result prevents full acceptance.
- Approvals are one-use or session-bound, with persistent rules written only through an explicit user control. A one-use elevation never widens a shared runtime proxy or another invocation.
- A one-use grant covers one logical tool action, including that action's reviewed read/access/write helpers until settlement. A separate toolCallId cannot reuse the grant.
- The reviewer child receives a typed deterministic decision as an input seam for its offline unit tests. It does not edit or secretly reimplement the sibling policy engine.
- Start in read-only or workspace-write profiles and retain immutable hard-deny paths for guard control files and synthetic protected data. Treat model/tool text as untrusted data for policy mutation.
- Verify caller cancellation and configured review/execution deadlines at final consumers using controlled fixtures; preserve model/UI timeout milliseconds and BashOperations timeout seconds.
- Qualify Darwin ARM64 and supported Linux independently before claiming those platforms. Missing Linux access or a nested-sandbox restriction creates an explicit blocked proof and never a green cross-platform result.
- Contract changes after wave 1 return to child 01, invalidate dependent hashes/readiness and require affected suites to rerun before integration continues.
